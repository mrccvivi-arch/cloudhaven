# Cloudhaven v0.1

Cloudhaven 是独立的治愈系第三人称 3D 探索原型。玩家可以照顾灰色龙猫棉花糖，穿过森林收集物品，再前往天空群岛。

## 运行与部署

需要 Node.js 20.19+ 或 22.12+，以及支持 WebGL 2 的浏览器。

```sh
npm ci
npm run dev
npm test
npm run build
npm run preview
```

使用终端显示的地址打开游戏。将 `npm run build` 生成的 `dist/` 部署到任意静态站点，部署后即可在 iPad Safari 打开。GitHub Pages 的 **Source** 请选择 **GitHub Actions**，仓库的 Pages 工作流会自动发布 `dist/`。直接发布 `main` 的源码目录时，浏览器无法解析 Three.js 的模块导入。用同一局域网测试时，可在 iPad 打开电脑的局域网地址和 Vite 显示的端口。

## 玩法

- **iPad**：左下摇杆移动，右半屏拖动转镜头。右下 **Jump** 支持在另一只手仍按住摇杆时触发。靠近物体时会出现互动按钮。
- **键盘与鼠标**：WASD 或方向键移动，鼠标拖动转镜头，Space 跳跃，E 互动。
- **悬浮栖息云**：按跳跃登上浮云，点按一侧的月牙储物舱存取原有库存。平坦的地块预留给建造。
- **森林探索区**：沿浅色小路前进，靠近地面带光圈的木材、小石头与种子后收集。穿过小溪木桥，和紫色拱门互动进入天空群岛。
- **天空群岛**：走过木桥，沿前方草地跑跳两次，点亮观景台。落下会回到最近的安全岛。起点和终点的拱门均可返回森林。
- **昼夜与月光能量**：白天 06:00–18:00 持续 12 分钟，夜晚 18:00–06:00 持续 8 分钟。白天移动或跳跃会缓慢消耗月光能量。夜晚在无遮挡处每秒恢复 0.5 点，充能时棉花糖周围会出现淡蓝光晕和星光。能量耗尽时仍可移动、跳跃和互动。打开背包或切到后台时，游戏时间暂停。
- **存档**：位置、区域、检查点、物品、已发现记录、基地互动、游戏时间和月光能量保存在本浏览器的 `cloudhaven-save-v1` 中。空中退出时恢复上一个安全位置。

## iPad Safari 测试

1. 在电脑运行 `npm run dev`，用同一 Wi‑Fi 下的 iPad Safari 打开 Vite 显示的 Network 地址。横竖屏各打开一次，确认左上状态栏、左下摇杆、右下跳跃和右上背包均可正常使用。用两只手同时移动和跳跃，再拖动右侧转镜头。
2. 新档从 09:00 开始。白天走动、跳跃，观察能量下降。回到悬浮栖息云，跳上云面并点按月牙，确认可以打开储物界面并存取物品。
3. 保持游戏在前台并关闭背包，新档约 9 分钟后进入夜晚。观察天空平滑变暗，确认小路和物品清楚可见。先在基地小路等待充能并边走边观察光晕、星光和头顶月亮，再走到基地后方屋檐下或森林树冠下，确认能量停止恢复。可拖动镜头查看天空中的月亮和星星。
4. 记下时间和能量，刷新同一地址，确认从已保存的状态继续。切换到其他标签页约 30 秒再返回，检查游戏时间没有跳过这段后台时间。

## 项目结构

`map.js` 定义地图、地形、交互点和检查点。`world.js` 和 `models.js` 负责场景及模型。`motion.js` 处理移动、重力和着地。`day-night.js` 推进游戏时间与能量，`moonlight.js` 更新天空、光照和充能效果。`controls.js` 和 `camera.js` 分别处理输入和镜头。`save.js` 验证本地存档，预留 `placements` 数组，每条记录包含 `id`、`type`、`position: {x,y,z}` 和绕 Y 轴旋转弧度 `rotation`。本版无放置按钮或制作配方。

## 月光水晶琴

从森林主路 `(5, 15)` 附近沿音符路牌往东南走，木质舞台位于 `(9, 19)` 的空地。地面小地图上的「♫」标记对应舞台坐标，点按可显示名称。靠近后点「月光演奏区 · 点击开始演奏」，用五个屏幕琴键自由弹奏，或体验三段记忆旋律。关卡解锁会保存在本地。用设备本地日期计算，每天从第一关连过三关可领一次最多 10 点月光能量。

在 iPad Safari 横屏和竖屏各试一次。点「演奏」后确认五键可同时显示，逐个试听并快速连按，确认水晶和琴键都会亮。进入挑战，先故意弹错一次，再重听并完成三关。刷新后检查已解锁关卡和当天领取状态。点「退出」后用摇杆、右侧拖动和跳跃确认操作恢复。

## 观景台与音效

从森林紫色拱门进入天空群岛，走过木桥并跳过两处岛间空隙。到最后一座岛，靠近中央灯柱后点「点亮观景台」。朝云海方向观察约两秒的符文、光环、星光和彩云变化。点「熄灭观景台」可在约 1.5 秒内恢复原状。两种状态都会在刷新后恢复。

在屏幕右上角的「设置」里调整音效和音量。iPad Safari 需要先触摸游戏，随后可以试听脚步、跳跃、落地、观景台和水晶琴。关闭音效时水晶、符文等视觉提示仍然有效。

## 碰撞调试

在游戏地址后加 `?debug=collision`，可查看角色碰撞体、树干、墙壁、石头、栏杆和桥面坡道。正常打开游戏时隐藏这些线框。

### 人间手记

靠近栖息云旁原有木板，点按栏面或使用互动按钮即可打开图文日记。日期按北京时间显示。未读新帖用木板旁的小星星提示，已读状态保存在当前浏览器。

- 同步账号为 `insomniavi.bsky.social`。首次通过公开 API 解析 DID，后续沿用已记录的 DID。只同步独立原创动态及图片，视频保留正文。图片压缩成 WebP，原始替代文本保存在日记数据中。
- 在 **Actions → Deploy Cloudhaven to GitHub Pages → Run workflow** 选择 `main` 手动进行完整同步。首次同步分页读取历史，此后每小时增量检查、每周完整校验。GitHub 可能延迟计划任务。无变化的定时或手动同步不会提交或部署，推送代码时仍会构建部署。
- 换账号时，在仓库 **Settings → Secrets and variables → Actions → Variables** 设置 `DIARY_ACCOUNT` 为新账号的完整 handle，再运行工作流。新账号同步成功后才替换旧快照。也可在本地通过同名环境变量设置，安装 ImageMagick 后运行 `node scripts/sync-bluesky.mjs --full`。
- 数据在 `public/diary.json`，图片在 `public/diary-media/`。Vite 将它们复制到 GitHub Pages 静态资源路径。原新闻脚本保留为独立工具，自动取稿已停用。
- 定时任务停用时，在 Actions 重新启用工作流并手动运行。Pages 发布来源仍应为 GitHub Actions，仓库规则需允许该工作流向 `main` 提交数据。同步失败时检查 Actions 日志，恢复后重跑，已发布快照会保留。若数据已提交但 Pages 部署失败，在该运行记录中选择 Re-run failed jobs。
- 日记和媒体是公开资源。对于 Bluesky 托管账号，只有完整校验发现缺失且账号数据服务器明确返回记录不存在时，才清除删除的帖子和无引用图片。迁移到其他托管服务后，无法确认的缺失帖子会保留。删除当前静态文件不会自动清除 Git 历史、缓存或其他公开副本。
